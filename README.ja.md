# Kura 🔐

**Kura**（蔵）は、`.env` ファイルのシークレットを難読化し、型安全なSwiftコードを生成する、純粋なSwift製CLIツール（`kura-generator`）です。

Rubyは不要で、Xcode Cloud でそのまま連携できるように設計されています。

> [!NOTE]
> Kuraが行っているのは XOR + salt による**難読化**であり、暗号学的に安全な**暗号化**ではありません。生成された `KuraKeys.swift` にはエンコード済みバイト列と復号に使う salt の両方が埋め込まれているため、ソースコードや実行バイナリにアクセスできる相手であれば容易に復元できてしまいます。狙いはあくまで「バイナリを `strings` した際に平文のシークレットがそのまま出てこないようにする」ことであり、真に秘匿すべき値（サーバー専用の秘密鍵など）をこの仕組みだけで守ることはできません。

特徴
----

- ✅ Ruby不要、外部ランタイム不要 — 純粋なSwiftのみ
- ✅ ただのSwiftPM実行ファイル（`kura-generator`）— Xcodeプロジェクトに組み込む必要もプラグインのサンドボックス制約もなし
- ✅ `ci_post_clone.sh` 経由で **Xcode Cloud** と連携可能
- ✅ XOR + salt による難読化（シークレットを平文で保存しない）
- ✅ グローバルシークレットと環境ごとのシークレットに対応
- ✅ `.arkana.yml` からの移行にも対応（対応オプションは一部）

インストール
------------

**推奨:** アプリ本体のXcodeプロジェクトには追加せず、専用の `BuildTools/Package.swift` を用意してそこにKuraだけを閉じ込めてください。こうすることで、`Yams` などKura内部の依存関係がアプリ本体の依存グラフ（`Package.resolved`）に混ざるのを防げます（`SwiftFormat` などのビルドツールを `BuildTools/` に隔離するのと同じ考え方です）。

```swift
// BuildTools/Package.swift
// swift-tools-version:5.9
import PackageDescription

let package = Package(
    name: "BuildTools",
    platforms: [.macOS(.v13)],
    dependencies: [
        .package(url: "https://github.com/CH3COOH/Kura.git", from: "1.0.0"),
    ],
    targets: [
        .target(
            name: "BuildTools",
            dependencies: [
                .product(name: "kura-generator", package: "Kura"),
            ],
            path: ""
        ),
    ]
)
```

`BuildTools/` にはターゲット用の空ファイル（例: `Empty.swift`）を1つ置いてください。

すでに純粋なSwiftPMパッケージ（`.xcodeproj` を持たないプロジェクト）であれば、`BuildTools` を作らずアプリ自身の `Package.swift` に直接 `dependencies` として追加しても構いません。その場合はそのパッケージのルートで `swift run kura-generator` を実行するだけです（`BuildTools` を使う場合は後述の通り `--package-path BuildTools` を付けてください）。

設定
----

プロジェクトルートに `.kura.yml` を作成します。

```yaml
import_name: KuraKeys      # 生成する Swift モジュール名
result_path: .             # KuraKeys/ を置くディレクトリ
swift_declaration: internal # internal / public

global_secrets:
  - API_KEY
  - ANALYTICS_TOKEN

environments:
  debug:
    - DEBUG_ENDPOINT
  release:
    - RELEASE_ENDPOINT
```

`.arkana.yml` も設定ファイルとして読み込めますが、Kuraが対応するオプションのみが反映されます（Arkanaの全オプションに対応しているわけではありません）。

使い方
------

### ローカル開発

`.env` をプロジェクトルートに置きます（`.gitignore` に追加すること）。

```
API_KEY=your_api_key_here
ANALYTICS_TOKEN=your_token
DEBUG_ENDPOINT=https://dev.example.com
RELEASE_ENDPOINT=https://example.com
```

生成を実行します（`.kura.yml` / `.env` と同じ階層＝プロジェクトルートで実行してください）。

```bash
$ swift run --package-path BuildTools kura-generator
```

`swift run --package-path` はビルドこそ指定したパッケージ（`BuildTools`）を使いますが、生成された実行ファイル自体は**呼び出し時のカレントディレクトリ**で動作します。そのため `.kura.yml` / `.env` の相対パス（デフォルト値）がそのまま解決され、オプションを明示的に渡す必要はありません。

生成された `KuraKeys/` をローカルパッケージとしてプロジェクトに追加します。

```swift
// アプリの Package.swift または Xcode の Package Dependencies
.package(name: "KuraKeys", path: "KuraKeys")
```

### Xcode Cloud

`.env` は不要です。ワークフロー設定で各キーを **Environment Variables** として登録し、`ci_post_clone.sh` に以下を追加するだけです。

```sh
#!/bin/sh
set -e
cd "$CI_PRIMARY_REPOSITORY_PATH/path/to/project"  # .kura.yml と同じ階層へ
swift run --package-path BuildTools kura-generator
```

生成されるコード
----------------

```swift
// KuraKeys/Sources/KuraKeys/KuraKeys.swift
// AUTO-GENERATED by Kura (https://github.com/CH3COOH/Kura) — DO NOT EDIT

private func _kuraDecrypt(_ encoded: [UInt8], salt: [UInt8]) -> String { ... }

internal enum KuraKeys {
    internal static var apiKey: String {
        let encoded: [UInt8] = [0x3F, 0x1A, ...]
        let salt: [UInt8]    = [0xAB, 0xCD, ...]
        return _kuraDecrypt(encoded, salt: salt)
    }
}

internal enum KuraKeysDebug {
    internal static var debugEndpoint: String { ... }
}

internal enum KuraKeysRelease {
    internal static var releaseEndpoint: String { ... }
}
```

アプリ側では通常通り使えます。

```swift
import KuraKeys

let key = KuraKeys.apiKey
let endpoint = KuraKeysRelease.releaseEndpoint
```

オプション
----------

```bash
$ swift run --package-path BuildTools kura-generator -- \
    --config path/to/.kura.yml \   # デフォルト: .kura.yml → .arkana.yml の順で探索
    --dotenv path/to/.env \        # デフォルト: .env
    --output path/to/output        # デフォルト: .kura.yml の result_path
```

よくある質問
------------

### cocoapods-keys ではダメですか？

CocoaPodsは、2026年12月に読み取り専用になることを発表しました。これはライブラリがアップデートされなくなるということを意味しています。プロジェクトで積極的に使い続けるのが難しくなったため、CocoaPodsに依存しない構成へ移行しました。Kuraは純粋なSwiftPMベースで動作するため、CocoaPodsの導入が不要です。

### Arkana ではダメですか？

Arkanaは優れたツールで、Kuraも設定ファイルの構造など多くの部分を参考にしています。ただしArkanaはRuby製で、ビルド時にRubyGems経由で依存gemを解決する必要があり、Xcode CloudからRubyGemsのサーバーへの接続が失敗することがあります。その度にビルドが止まってしまい、開発が滞ることがあったため、外部ランタイムやネットワーク越しの依存解決を必要としない純粋なSwift製CLIとしてKuraを作りました。
